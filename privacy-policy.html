Privacy Policy

Last updated 16 November 2026

This policy covers the De’vyora studio application (also referred to as Casa de Aurum), the private web tool the studio uses to keep its tile catalogue, build mood boards, hold a reference image library and record client wishlists.

It is not a consumer product and it has no public sign-up. Accounts are created by the studio for its own staff. This policy explains what the application holds, what it does with a connected Google account, and what it never touches.

1. Who runs this application

The application is operated by the De’vyora studio for its own showroom and design work. The studio is the controller of everything described below.

2. What the application stores

Staff accounts

  • Name, email address, role, and a one-way hash of the password (the password itself is never stored).
  • Optionally, a passkey credential, if that member chose to enable one on their device.
  • Sign-in activity, so the studio can see who did what.

Studio content

  • Tile and catalogue records entered or extracted by the studio.
  • Mood boards, print boards and generated visualisations.
  • Reference images uploaded to the studio’s library.
  • Client wishlists: the client’s name, an optional mobile number, and the pictures that client selected in the showroom. These are entered in the showroom by the client or by staff, and are used only to prepare that client’s proposal.

3. Google account data

The application can be connected to one Google account — the studio’s own — so that the pictures it holds are stored in the studio’s Google Drive rather than on this server. The connection is made once, by the studio owner, from inside the application. Nobody else is asked to sign in with Google, and clients are never asked for a Google account.

The scope requested

https://www.googleapis.com/auth/drive.file

This is Google’s narrowest Drive scope. It grants access only to files this application itself creates, and to folders or files the account holder explicitly picks and hands to it. It does not grant, and the application cannot obtain, a view of the rest of that Google Drive.

What it does with that access

  • Creates folders inside the one folder the owner chose — by theme and room for the reference library, and one folder per client for wishlists.
  • Uploads the studio’s pictures into those folders.
  • Reads back the identifier and the view or thumbnail link of each file it created, so the pictures can be displayed inside the application.
  • Deletes a file it created, when a member of the studio removes that picture from the library.

What is kept on this server

  • The identifier of the folder the owner chose.
  • The identifiers and links of the files the application created.
  • The Google refresh token, so uploading keeps working without the owner reconnecting each time. It is encrypted at rest and is never shown in the interface, written to logs, or sent to a browser.

What is never requested

  • The Google account’s email address, name or profile — no identity scope is requested at all.
  • Gmail, Contacts, Calendar, Photos, or any other Google service.
  • Any file in Drive that the application did not create or was not explicitly given.

4. Where pictures are sent for generation

When a member of the studio generates a mood board or a room visualisation, the reference picture they chose and the catalogue tile images are sent to Google’s Gemini API, which produces the generated image. That is the only place studio pictures are sent outside this application and the studio’s own Drive, it happens only when a member of the studio asks for a generation, and the result comes back to the studio.

5. Limited Use

De’vyora’s use and transfer of information received from Google APIs to any other app adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Concretely: data obtained through the Google Drive connection is used only to provide the features described above. It is not sold, not transferred to anyone else, not used for advertising, not used to build profiles, and not used to train any machine-learning model. No human reads it except members of the studio using the application.

6. How long it is kept, and how to end it

  • Studio content is kept for as long as the studio keeps it, and is deleted when the studio deletes it.
  • A client’s wishlist is deleted when the studio deletes that client.
  • The Google connection lasts until it is ended. The owner can disconnect it inside the application, which deletes the stored refresh token; the account holder can also revoke it at any time at myaccount.google.com/permissions.
  • Files already uploaded belong to the studio’s own Google Drive and stay there after a disconnection. Removing them is done in Drive.

7. Who else sees it

Nobody. The application does not sell or rent anything it holds, shows no advertising, and runs no third-party tracking or analytics. It is served by a hosting provider and uses a database and Google’s own APIs to do the work described above; those providers process data on the studio’s behalf and for no other purpose.

8. Security

  • All traffic is served over HTTPS.
  • Passwords are stored only as one-way hashes.
  • Secrets, including the Google refresh token, are encrypted at rest.
  • Every screen beyond the sign-in page requires an authenticated session, and each action is additionally checked against that member’s role.

9. Children

The application is a professional tool for the studio’s staff. It is not directed at children and is not intended to be used by them.
